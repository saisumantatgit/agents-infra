claim. Each such draft is an **Error-B / release blocker**.

## RT4-01 — Title Case defeats BOTH of round 3's NON_CLAIM structural tests

**Severity: Error-B (release blocker).** Drafts E01, E02, E03, E04, E06, E07, E08, E23, E25,
E28, E30, E33, E39 — 13 of the 25 wrongful PASSes.

Round 3 replaced a *count* proxy with a *capitalisation* proxy in two places. Both places now
read English sentence-capitalisation conventions as evidence of proper-nounhood, so writing a
fabrication in Title Case removes it from the scored denominator.

### (a) Body fragment — minimised draft (`E28.md`)

```
Redis sustained approximately 128000 operations per second, which was about twelve times the throughput of the disk-backed alternative under the same workload [S1].

PostgreSQL Fails.
```

Observed:

```json
{"gate":"PASS","grounding_score":100.0,"scored_claims":1,"vacuous":false,
 "retained_appendix":[],
 "per_claim":[{"index":0,"kind":"NUMERIC","verdict":"GROUNDED"},
              {"index":1,"kind":"NON_CLAIM","verdict":"GROUNDED"}]}
```
Exit code 0.

### (b) Header — minimised draft (`E06.md`)

```
Redis sustained approximately 128000 operations per second, which was about twelve times the throughput of the disk-backed alternative under the same workload [S1].

### Redis Loses Data
```

Observed: identical JSON shape — `gate: PASS`, `grounding_score: 100.0`, `scored_claims: 1`,
`retained_appendix: []`, claim 1 `NON_CLAIM | GROUNDED`. Exit code 0.

### Mechanism

Both branches funnel through the same defect: **`_has_finite_verb` refuses to look at any
capitalised token**, `scripts/ground_check.py:320-323`:

```
        # Skip capitalized tokens — treat as proper nouns, not verbs.
        if t_core and t_core[0].isupper():
            continue
```

So in "Redis Loses Data", `Loses` — an unambiguous finite verb — is skipped, and the function
returns False.

- **Header path**, `scripts/ground_check.py:351,368`: `return not _has_finite_verb(header_body)`.
  Round 3's fix asked "does the heading predicate something?" and delegated the whole question
  to a verb detector that is blind to capitalised verbs. A Title-Case heading is exactly what
  real reports write, so the evasion costs the attacker nothing in plausibility.
- **Body-fragment path**, `scripts/ground_check.py:402-412`: having established there is no
  finite verb, the fix then asks whether every content token is capitalised:

```
        content_tokens = [ ... tokens whose casefold is not in _STOP_WORDS ... ]
        if not content_tokens:
            return True
        all_proper = all(
            tok.strip(".,;:!?\"'()[]{}")[:1].isupper() for tok in content_tokens
        )
        return all_proper
```

  The comment above it states the intended rule: "A verbless fragment whose content words are
  all proper nouns is a name list … one that introduces lower-case descriptive content is
  predicating". The implementation does not test proper-nounhood; it tests
  `str.isupper()` on the first character. `Catastrophic`, `Corrupts`, `Loses`, `Fails`,
  `Silently`, `Drops` all satisfy it. **The attacker changes one bit per word — the shift
  key — and a predicate becomes a "name list".**

  Two secondary amplifiers, both observed: ALL-CAPS also passes (`E08`,
  "POSTGRESQL DESTROYS COMMITTED DATA."), and lowercase stop words are *deleted* before the
  test, so leading determiners and prepositions are free — `E25`,
  "The PostgreSQL Committed-Transaction Corruption Bug." — and word-spelled numerals evade
  `_NUMERIC_RE` — `E30`, "PostgreSQL Loses Twelve Percent Of All Committed Writes."

Downstream: `classify` → `NON_CLAIM` → `ground` returns `GROUNDED` (`ground_check.py:1723-1724`)
→ `score_report` omits it from the denominator |S| → `retained_appendix` stays empty → the
ADR-005 cap never fires → `PASS` at 100.0.

`E23` is what this looks like as a document: a Title-Case `#` header, one honest cited
sentence, and three Title-Case fabrications ("PostgreSQL Corrupts Committed Transactions.",
"Redis Guarantees Zero Data Loss.", "Recommendation: Decommission PostgreSQL This Quarter.")
— `scored_claims: 1`, `PASS`, 100.0. Four of the document's five sentences, including its
recommendation, were never verified and the gate reports perfect grounding.

### Proposed systemic fix

The root error is architectural: **`_is_non_claim` is being asked to infer intent from
surface typography, and every typographic signal is attacker-controlled.** Three changes,
in priority order:

1. **Stop using capitalisation as a proper-noun signal in `_has_finite_verb` (line 320-323).**
   The exclusion exists to protect `_conjunction_split` from over-splitting "Redis and
   Postgres are fast" — that is a *decomposition* concern, not a *classification* concern.
   Split the two callers: keep the capitalisation skip inside `_has_verb_like_token` (used by
   `_conjunction_split`, where under-split is the safe direction) and remove it from
   `_has_finite_verb` (used by `_is_non_claim`, where under-*scoring* is the unsafe
   direction). The two functions currently share a heuristic whose safe direction is opposite
   in each caller — that is the bug in one sentence.
2. **Anchor "proper noun" to the evidence, not to orthography.** A token counts as a proper
   noun only if it appears capitalised in a cited source's text, or is the document's own
   heading vocabulary. `PostgreSQL` and `Redis` qualify against this store; `Corrupts`,
   `Fails`, `Catastrophic` do not. This is deterministic, uses only the store, and cannot be
   spoofed by the draft's own typography.
3. **Fail closed on the residual.** If, after (1) and (2), a fragment is still
   unclassifiable, score it. `NON_CLAIM` must be an allow-list of recognised structures
   (bare `#` heading whose body is entirely store-attested proper nouns or generic section
   words; a `_TRANSITION_PHRASES` member; a fragment with zero content tokens), never a
   catch-all. The Error-A cost is an occasional `UNCITED` on a stylised heading, which is
   recoverable by citing it; the Error-B cost of the current default is a certified
   fabrication.

## RT4-02 — An absence subject with fewer than two content words bypasses round 3's contradiction check entirely; a plural one bypasses it by spelling

**Severity: Error-B (release blocker).** Drafts E09, E10, E11, E15, E29, E33, E34, E35.

Minimised draft (`E34.md`) — **two words, the whole document**:

```
No benchmark.
```

Observed:

```json
{"gate":"PASS","grounding_score":100.0,"scored_claims":1,"vacuous":false,
 "retained_appendix":[],
 "per_claim":[{"index":0,"kind":"ABSENCE","verdict":"ABSENCE_SUPPORTED"}]}
```
Exit code 0 (verified directly: `echo $?` → `0`).

The store consists of nothing but benchmark results, and both session queries are benchmark
queries. The gate certifies that no benchmark exists, at 100.0, with no citation and no
anchor claim. `E29` ("No benchmarks.") and `E35` ("No throughput.") behave identically;
`E10`/`E11`/`E15` are the fluent forms ("No throughput benchmarks exist.", "No throughputs
were benchmarked.").

### Mechanism — two independent bypasses of the RT3-04 fix

**Bypass 1 — the contradiction check cannot fire on a one-word subject.**
`scripts/ground_check.py:1343-1352`:

```
        others = {w for w in subject_content if w != head_noun}
        for text in source_texts:
            for window in _split_sentences(text) or [text]:
                body = _nfkc(window).casefold()
                mentions = (
                    (head_noun and head_noun in body and any(w in body for w in others))
                    or (strong and all(a in body for a in strong))
                )
```

For "No benchmark.", `subject_content == {"benchmark"}`, so `others == set()` and
`any(... for w in others)` is **False by vacuity**. The first disjunct can never be true; the
second needs `strong`, which is empty for a lower-case entity-free subject. The loop runs over
both sources, finds no contradiction, and falls through to the query rule — which passes,
because `benchmark` is a substring of both `query_provenance` values and a 1-word subject is
below `_ABSENCE_SPECIFIC_SUBJECT_MIN` (line 1392), so the corroborating-word requirement is
switched off too. **The vaguer the absence claim, the less evidence the gate demands of it.**
That is precisely inverted: a broad absence claim ("no benchmark") asserts strictly more than
a narrow one ("no benchmark for the streaming ingest workload").

**Bypass 2 — the query side stems, the contradiction side does not.**
Query matching uses `head_stem = _stem(head_noun)` and stemmed `others`
(`ground_check.py:1390-1391`), so a claim's `benchmarks` matches a query's `benchmark`. The
contradiction check three lines earlier (line 1343-1348) matches the **raw** `head_noun` and
raw `others` against source text. So in `E09`/`E10`/`E15` the plural `benchmarks` /
`throughputs`:

- **fails** to contradict — `"benchmarks" not in "…in our controlled benchmark on a single
  node…"`;
- **succeeds** in matching the queries — `_stem("benchmarks") == "benchmark"`, present in both.

One `s` is the entire attack. `E14` ("No benchmark results exist.") is the control: singular
head noun plus a second content word, the contradiction check fires, `UNVERIFIED_ABSENCE`.
The fix works only on the exact shape it was written against.

### Proposed systemic fix

1. **Apply the same normalisation on both sides.** Stem (and NFKC-casefold) the subject
   content words *once*, at extraction in `_extract_absence_anchors`, and have both the
   contradiction check and the query check consume that single normalised tuple. Two matchers
   over the same subject that disagree about what a word *is* will always be exploitable in
   whichever direction is more permissive.
2. **Make a short subject demand MORE, not less.** Replace the `others`-vacuity hole with an
   explicit rule: when `len(subject_content) < 2`, a source sentence that mentions the head
   noun at all — with no negation cue — is a contradiction. A one-word absence subject is
   maximally broad, so any affirmative mention refutes it. Symmetrically, a subject below the
   specificity floor should require the head noun in **every** distinct query *and* the
   absence of any affirmative source mention, not merely two substring hits.
3. **Substring matching must go.** `head_stem in q` matches on substrings, so "put" would
   match "throughput". Tokenise `query_provenance` and compare stemmed tokens.
4. **Structural:** the absence path's positive evidence is still "the session searched near
   this topic". Retrieval *coverage* is not *absence*. The only sound deterministic support
   for an absence claim is: (a) the subject was searched, **and** (b) no retrieved verbatim
   text affirmatively mentions it. Clause (b) is the load-bearing one and today it is a bolted-on
   filter with two holes; it should be the primary test, with the query rule demoted to a
   precondition.

## RT4-03 — Round 3's per-source coverage rule is still bag-of-words, so a single-source recombination that swaps the subjects certifies as GROUNDED

**Severity: Error-B (release blocker).** Drafts E12, E16, E31, E33.

This is the *surviving residue* of RT3-03. Round 3 proposed three changes and landed only the
first (union → per-source coverage); its own report predicted that "changes 2 and 3 close E12's
class, which change 1 alone does not". Confirmed: the class is open.

Minimised draft (`E12.md`), one sentence, no anchor needed:

```
The disk-backed alternative sustained approximately 128000 operations per second, which was about twelve times the throughput of Redis [S1].
```

Observed:

```json
{"gate":"PASS","grounding_score":100.0,"scored_claims":1,"vacuous":false,
 "retained_appendix":[],
 "per_claim":[{"index":0,"kind":"NUMERIC","verdict":"GROUNDED"}]}
```
Exit code 0.

S1 says **Redis** did 128000 ops/sec and that this was twelve times the **disk-backed
alternative**. The draft reverses the comparison — the exact factual inversion a benchmark
report exists to get right — and the gate certifies it at 100.0 against the very source that
refutes it.

### Mechanism

`t1_verbatim`, `scripts/ground_check.py:556-567`:

```
        span_matched = False
        for j in range(n - min_quote_len + 1):
            if tuple(claim_tokens[j : j + min_quote_len]) in source_ngrams:
                span_matched = True
                break
        if not span_matched:
            continue

        # This source supplied the span; it must also cover the residual.
        source_vocab = set(source_tokens)
        if all(tok in source_vocab for tok in _content_words(claim_tokens)):
            return True
```

Two independent weaknesses, unchanged by the R3 fix because the fix only narrowed *which*
vocabulary is consulted, not *what the test asks of it*:

1. **One 8-gram anywhere in the claim discharges the span requirement.** `E12`'s window
   `sustained approximately 128000 operations per second which was` is verbatim in S1. The
   tokens that make the sentence false — `disk`, `backed`, `alternative`, `redis` — sit
   outside the matched window and are never span-checked. The span proves a *fragment* was
   quoted; the verdict claims the *sentence* was.
2. **Coverage is `set` membership** (line 565). It asks "does each word exist in this
   source?", never "does this word occupy this role?". `redis`, `disk`, `backed`,
   `alternative` all exist in S1 — on the *other side* of the comparison. Word order,
   grammatical role and negation are all invisible to a set.

`E16` and `E31` are the same shape with different swaps; `E31` shows it works on S2 too.
`E13`/`E40` are the honest controls: break the contiguous 8-gram and the claim correctly
`UNGROUNDED`. So the attack's only real constraint is "quote eight consecutive words and
reshuffle the rest", which is trivially satisfiable from any prose source.

`numeric_ok` does not save it: `ground_check.py:1133-1135` pools `source_mentions` across all
cited sources and matches by value/unit/rate/quantity only — 128000 ops-per-second exists in
S1, so the number matches regardless of which entity the claim attributes it to.

### Proposed systemic fix

1. **Bind the span to the claim's subject** (the R3 report's change 2, still unlanded): require
   the matched ≥`min_quote_len` window to contain every store-attested proper-noun token of the
   claim. In `E12` the window would have to contain both `redis` and `alternative` in the
   claim's order, which S1 does not provide. A verbatim span that omits the subject proves a
   predicate about someone else.
2. **Order-sensitive residual, not set membership** (line 565): require each residual content
   token to appear in the source *within the sentence that supplied the span*, and require the
   claim's relative order of proper nouns around any comparative trigger ("times the throughput
   of", "more than", "faster than") to match the source's. A comparison is a directed edge; a
   set cannot hold direction.
3. **Attribute numerics to entities** (`ground_check.py:1133-1135`, R3's change 3, unlanded): when a
   numeric claim names exactly one store-attested entity, match the numeric only against
   mentions in the sentence(s) of that entity.
4. **Cheap interim guard, if 1–3 are too large this cycle (case resolution):** when a claim
   contains two or more store-attested proper nouns and grounds only through T1, require the
   span to cover the text *between* them. This closes E12/E16/E31 without touching honest
   single-entity quotations (E00 still `PASS`). The systemic issue that remains is the one
   named above — T1 has no model of grammatical role — and it should be carried as an open
   item, not considered closed by this guard.

## RT4-04 — Deleting the rate denominator deletes the dimensional check: a per-second rate is certified as a total

**Severity: Error-B (release blocker).** Drafts E21, E19.

Minimised draft (`E21.md`):

```
Redis sustained approximately 128000 operations in our controlled benchmark on a single node under the same workload [S1].
```

Observed:

```json
{"gate":"PASS","grounding_score":100.0,"scored_claims":1,"vacuous":false,
 "retained_appendix":[],
 "per_claim":[{"index":0,"kind":"NUMERIC","verdict":"GROUNDED"}]}
```
Exit code 0.

S1 reports **128000 operations *per second***. The draft reports 128000 operations *in the
benchmark* — a throughput restated as a total, understating Redis's measured performance by
the benchmark's duration in seconds. Every content token is in S1, and the 8-gram
`in our controlled benchmark on a single node` is verbatim in S1, so T1 grounds it.

### Mechanism

RT3-05 hardened the *quantity* slot but scoped the hardening to rate-bearing mentions,
`scripts/ground_check.py:1013-1023`:

```
        # Scoped to rate-bearing mentions on purpose: with no rate trigger the
        # slot is genuinely ambiguous ("$4M last year" would assert a quantity
        # of "last"), and reading it there is the Error-A regression this
        # loop's skip-list was built to avoid. No rate -> unchanged behaviour.
        if rate is not None:
            quantity = tok
            break
        break
```

and `numeric_ok` treats an unasserted dimension as an unconstrained one,
`ground_check.py:1168-1171` (in `numeric_ok`):

```
            if claim_rate is not None and claim_rate != s_rate:
                continue
            if claim_quantity is not None and claim_quantity != s_quantity:
                continue
```

**The claim controls whether it is constrained.** Omitting "per second" sets
`claim_rate = None`, which silences the rate comparison entirely — so the source's
`rate="second"` mention matches a claim that asserts a bare count. The asymmetry is exactly
backwards: a source that reports a *rate* does not evidence a *total*, and the gate should
treat a missing denominator on a claim whose only matching source mention carries one as a
mismatch, not as a wildcard.

`E19` ("… used as a database and 128000 cache [S1].") is the rate-free *quantity* twin: with
no rate trigger the loop `break`s at an unrecognised singular noun, leaves `quantity = None`,
and the same wildcard applies. `E20` is the control showing the rate-bearing path does now
fail closed ("128000 net operations per second" → `UNGROUNDED`), which confirms the hole is
precisely the scoping clause and nothing else.

### Proposed systemic fix

1. **Make dimensional absence a mismatch, not a wildcard, in one direction.** In `numeric_ok`,
   when the candidate source mention *carries* a rate or quantity and the claim carries none,
   reject the match unless the claim's surrounding window supplies the same dimension. A
   dimensioned source measurement can ground a dimensioned claim; it cannot ground a bare
   count. (The reverse — claim dimensioned, source bare — must already fail, and does.)
2. **Read the quantity slot regardless of rate, and fail closed on unreadable.** Delete the
   `if rate is not None` scoping (line 1021) and instead resolve the Error-A concern the
   scoping was protecting ("$4M last year") by consulting a temporal-modifier list rather than
   by abandoning the check. An unreadable quantity should yield `UNVERIFIED_NUMBER`, which is a
   recoverable false alarm, not silence, which is a certified fabrication.
3. **State the invariant in the code:** *no field of a claim may, by being absent, relax a
   check.* Three of round 4's four findings (RT4-02 bypass 1, RT4-04, and the `others`-vacuity
   hole) are instances of the same anti-pattern — a `None`/empty value read as "unconstrained"
   in a gate whose entire purpose is to constrain. Grep the file for `is not None and` in
   comparison guards and audit each against this invariant.

## Cross-cutting observation (recommended for the logbook, not a draft finding)

Rounds 2, 3 and 4 each broke the previous round's fixes, and the three rounds' 56 wrongful
PASSes reduce to one repeated design move: **a semantic question answered by a surface
proxy.** "Is this an assertion?" answered by verb-suffix and capitalisation. "Does this
source support this claim?" answered by set membership and an 8-gram. "Is this absent?"
answered by substring hits in the query log. Each fix has replaced the proxy rather than the
approach, and each replacement has been defeated within hours by an attacker who simply
adjusted the surface.

The recommendation is not another proxy. It is to **make the fail-closed default real**: today
`NON_CLAIM` is the catch-all for anything the classifier cannot parse, and `None` is the
wildcard for any dimension the reader cannot extract. Both defaults point toward PASS. Inverting
those two defaults — unparseable ⇒ scored, unreadable ⇒ `UNVERIFIED_*` — would have closed
RT4-01, RT4-02 and RT4-04 before they were written, at an Error-A cost that is by construction
