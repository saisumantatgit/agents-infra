## Prediction, recorded BEFORE the adversaries ran

**Path B is most likely to yield a real Error-B.** Its guard discriminates on
whether the author's segment ends in `;` or `.` — and CLAUDE.md's own law says
*never key a moat rule on a surface property the author controls.* Punctuation
is set by whoever writes the draft. The docstring defends `;` as chosen "for
grammatical reasons, not to satisfy the gate", which is an assumption about the
author's INTENT, and an attacker has no obligation to honour it.

Path C second: the 5-token lookback is a fixed window and the attacker chooses
where the span starts. Path A third.

**If path B comes back clean, this prediction was wrong and that is the finding.**

## The load-bearing conclusion, and it is larger than 14 bugs

Compare the two rows that matter:

```
ATTACK   Critics have argued for many years now that  | Redis loses data on restart
HONEST   Our own benchmark has shown repeatedly over  | Redis loses data on restart
         the past year that                           |
```

Same claim, same structure, same distance past the 5-token window, both a
`that`-complement of a reporting verb. **They are syntactically identical.** The
only thing separating them is whether the author endorses the attributing
subject — *Critics* versus *our own benchmark* — and that is a semantic
judgment about stance, not a property any deterministic rule reads off the text.

So three repairs are now ruled out **by evidence, not by taste**:

- **A wider lookback window** — turns the honest row red along with the attack.
- **A longer `_SPAN_HEDGE_TOKENS` list** — `maintain`, `so-called`, `debunks`
  and a Cyrillic `с` all defeated it, and the list can be extended forever
  because the attacker picks the verb.
- **A matrix-clause / parse-position rule** — both rows are complements. It does
  not separate them either.

**What remains is fail-closed and it has a price.** Refuse containment grounding
for any span embedded in a `that`-complement of a reporting verb, regardless of
who is reporting. That converts every one of these Error-Bs into Error-A on the
honest mirror. Under the moat invariant that is the correct direction — Error-A
is recoverable, Error-B is not — but it is a real cost and it lands on exactly
the honest short quotation that exact containment was built for (OI-T2-01).

**This is ADR territory, not a patch.** The quote-mining guard's premise — a
token blacklist over a fixed window — is unsound as a class, and I am not going
to close 13 findings with a fourteenth narrow rule. Recommendation and the
ruling it needs are in the Decisions section below.

## Path B — my prediction was wrong, and the refutation is the finding

I predicted before the round ran that the `;` discriminator in
`_propagate_across_semicolon` would yield a real Error-B, on the grounds that it
keys on a surface property the author controls.

**Half right, and the wrong half.** The behaviour is exactly as predicted and
worse than I expected — one keystroke flips the same assertion from FAIL to
PASS, and propagation also crosses paragraph breaks and Markdown list-item
boundaries. I verified both.

```
"… with AOF persistence; the cluster was tested for three hours [S1]."  -> PASS
"… with AOF persistence. The cluster was tested for three hours [S1]."  -> FAIL
```

But the adversary ran the control I had not thought to specify: cite the same
fabricated clause **directly**. It also PASSes. Propagation's output is exactly
`left + " [Sx]"`, and every downstream path strips markers before tokenizing —
so propagation cannot certify anything a self-citation could not. It removes the
UNCITED blocker and misattributes text; **it moves no Error-B.**

The Error-B is one level down, in **T1 itself**: after the 8-token verbatim
anchor, the residual coverage check is unordered **set membership**. `disabled`
sitting somewhere in the source licenses `with` in the claim. S1 says the
benchmark ran with AOF persistence *disabled*; the certified claim says it ran
*with* it. That is the RT4-03 argument-swap family, unclosed for **modifiers** —
and it is in the only tier that can grant a PASS.

Patching the `;` rule would have closed a fidelity defect and moved the Error-B
rate not at all. That is what the prediction got wrong, and it is worth more
than being right would have been.

### Needs Sai — two rulings, both Escalation #1 clause 1

**1. OI-MOAT-27 — the quote-mining guard's premise is unsound as a class.**
*Recommendation: adopt the fail-closed rule and pay the Error-A.* Refuse
containment grounding for any span embedded in a `that`-complement of a
reporting verb, regardless of who is reporting. **Why:** the attack and the
honest case are syntactically identical (proved above), so nothing deterministic
separates them, and the moat invariant says which way to fail when you cannot
tell. **What it costs:** honest attributed quotations start reading UNGROUNDED —
Error-A rises, on exactly the short quotation exact containment was built for.
**What would flip it:** if T3/NLI lands, it recovers this class directly, so the
cost is temporary rather than structural. This is your call because it moves the
Error-A/Error-B trade-off, which is clause 1 by its literal text.

**2. OI-MOAT-25's sibling — the report misquotes the author.**
syntok reconstruction turns `doesn't` into `doesnot`, so a draft quoting its
source **word for word** reads UNGROUNDED and the gate prints back a sentence
the author never wrote. *Recommendation: fix it, but only AFTER OI-MOAT-25.*
**Why the order matters:** restoring faithful text is PASS-enabling, and if it
landed while the contracted-hedge hole is open it would widen that hole rather
than close it. Sequence, not preference.
