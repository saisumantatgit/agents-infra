### The finding that matters most

`_span_is_hedged` and `_span_under_nonfactive_complement` were called from
**exactly one place** — `_claim_contained_verbatim`, the exact-containment
path. The ≥8-token contiguous-span path applied **neither**.

```
source:  It is not true that the Redis cache silently loses acknowledged
         writes on restart under default settings.
claim:   The Redis cache silently loses acknowledged writes on restart
         under default settings [S1].
verdict: GROUNDED     gate: PASS     score: 100.0
```

**The gate certified the exact negation of its own cited source.** Shorten the
identical shape below 8 tokens and it correctly FAILED. So the moat's
endorsement check fired for short claims and was silent for long ones —
**the author switches it off by typing more words.**

I reproduced this myself before accepting the adversary's report, per the
standing rule that reports are testimony and artifacts are evidence.

**This is the project's own law broken by the fix written to uphold it.**
*Never key a moat rule on a surface property the author controls.* Round 3
killed a token-count rule. Round 4 killed a capitalisation rule. This is
**claim length**, and it was found on J-19 — the whitelist — **the same day
J-19 shipped claiming to close the quote-mining family.** J-19's polarity was
right and its *wiring* was half-done; nobody checked which call sites the
guard actually reached.

**The transferable lesson is not about factivity.** It is: *when you add a
guard, enumerate its CALL SITES, not its cases.* Every red-team round in this
project has checked whether a rule is correct. None had checked whether it is
**reached**.

### The display I shipped this morning is among the findings

`evidence_basis` (D-35) was attacked deliberately, because shipping a new
surface unattacked is how every prior hole got in. It did not survive:

- **R8C-11 — its stated contract is FALSE.** I wrote that its branch order
  "mirrors `ground()` exactly, so the basis can never describe a path the
  verdict did not take." `ground` dispatches RELATIONAL first and
  `evidence_basis` **has no RELATIONAL branch**, so all four relational cases
  are misdescribed — including a two-source claim whose basis says "2 cited
  sources" in the row whose verdict exists precisely because only one carried
  the link. **The guarantee has been withdrawn from the docstring.** A wrong
  claim of record is worse than a known gap, because the gap gets rechecked
  and the guarantee does not.
- **R8C-09 — the fix reproduced the defect it was written to close.** An empty
  `query_provenance` renders as `""` and is counted: the exact blank-token
  presentation OI-UX-01 exists to eliminate.
- **R8C-04 — the store speaks in the gate's voice.** `query_provenance` is
  interpolated raw, so a retrieval tool's content can append "…and the gate
  verified this claim against 4 corroborating sources" to a sentence a
  customer reads as the gate's own.

**This vindicates attacking your own work the same day.** D-35 was written
carefully, reviewed against its own tests, and was wrong in three ways within
the hour. The tests I wrote for it could not find these, because they encode
what I believed the function did.
