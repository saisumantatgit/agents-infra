## ERROR-B 1 — `claim.citations` is built by `_CITATION_RE`, and 13 of 18 tested marker
## spellings never enter it. RELATIONAL and ABSENCE then certify PASS 100.0 — the two
## kinds J-25 exists to protect.

**Severity: ERROR-B (unrecoverable class). Pre-existing defect; it REFUTES the closure,
it is not a regression introduced by b8d4584.**

### Mechanism

`scripts/ground_check.py:437`

```python
_CITATION_RE = _re.compile(r"\[(?:S\d+[a-zA-Z]*|source:[^\]]+)\]")
```

No `re.IGNORECASE`. No tolerance for whitespace, punctuation, or separators inside the
brackets. `classify()` at `scripts/ground_check.py:716` populates the claim's citation
tuple from that regex alone:

```python
citations: tuple[str, ...] = tuple(_CITATION_RE.findall(text))
```

J-25's new guard (`scripts/ground_check.py:2595`) is

```python
if any(resolve(c, store) is None for c in claim.citations):
    return Verdict.UNVERIFIED_CITATION
```

`any()` over an empty-of-the-fake-marker tuple is `False`. A marker the regex does not
match is not an unresolved citation — it is **not a citation at all**. It is invisible to
the guard, invisible to `resolve()`, invisible to `evidence_basis()`, and it stays on the
page where the reader sees it.

FACTUAL and NUMERIC claims are protected *by accident*, not by design: the unmatched
marker's residual tokens survive `_strip_citations` and are therefore caught either by
T1's per-source coverage check (`all(tok in source_vocab ...)`,
`scripts/ground_check.py:1121`) or by the bracket digits leaking into `numeric_tokens`
→ `UNVERIFIED_NUMBER`. RELATIONAL and ABSENCE run **neither** of those: `ground_relational`
resolves only what is in `claim.citations`, and `check_absence` never inspects citations
at all. So the exposure lands precisely on the two kinds the commit message names.

### Systemic fix (this is a Systemic, not a Case, defect)

The invariant the gate needs is not "every marker matching `_CITATION_RE` resolves" but
**"every bracketed span that a reader would read as a citation resolves."** Two properties
worth having, and neither is author-controlled:

1. **Recognise brackets, then resolve, then refuse.** Treat *any* `\[[^\]\n]{1,80}\]` span
   as a candidate citation. If its normalised key is in the store → citation. If it is not
   → `UNVERIFIED_CITATION`, unless it is on an explicit non-citation allowlist
   (markdown link/image syntax `](`, checkbox `[ ]`/`[x]`, footnote `[^n]` if the project
   wants it). This inverts the default from "unrecognised ⇒ unconstrained" to
   "unrecognised ⇒ refuse", which is this repo's own stated law: *every "I don't know" must
   point AWAY from PASS.* It is strictly fail-closed and buys Error-A only on drafts using
   brackets for prose, which is recoverable.
2. **Confusable skeleton on the key before lookup**, per the global NFKC/TR39 rule, so
   `[Ѕ99]` cannot resolve-or-miss on a homoglyph.

Neither property is a length, a case, a count, or a punctuation pattern — i.e. neither is a
dial the draft's author owns.

Also worth the one line it costs: `_CITATION_RE` is the *sole* definition of "what is a
citation" and is consumed at 14 sites (`grep -n _CITATION_RE`). A gap in it is a gap in
`classify`, `_is_non_claim`, `_strip_citations`, `t1_verbatim`, `numeric_ok`,
`extract_arguments`, and the propagation rules simultaneously. That concentration is why
one regex flaw reopens a whole class — and it deserves a `CEILING:` note stating it.

## ERROR-B 2 — the same regex gap lets an invisible marker ride inside a NON_CLAIM

**Severity: ERROR-B, same root cause as finding 1. Recorded separately because it defeats
a DIFFERENT guard (`_is_non_claim`'s anti-gaming override), not the J-25 guard.**

`scripts/ground_check.py:598`:

```python
if _CITATION_RE.search(text):
    return False
```

This is the MOAT-SAFE override whose docstring promises that "a verbless sentence that
carries ... a citation marker is real, verifiable claim content and MUST NOT be excluded".
The promise is only as wide as the regex. A span carrying `[s99]` or
`[Source:acme-report]` reads as *no citation present*, so the override does not fire and
the span can leave the scored denominator via the header / verbless-fragment routes —
taking its visible fabricated citation with it.

This is **reproduced only at the classifier level**, not yet as an end-to-end PASS: the
remaining NON_CLAIM routes that still admit an assertion are the known-open verb-final
header (OI-MOAT-19) and the zero-content-word route, so an end-to-end PASS needs OI-MOAT-19
to be open too — which it is, with a strict-xfail tripwire. I am therefore labelling the
*end-to-end* consequence **unreproduced** and the *guard defeat* **confirmed**: the
citation override at line 598 demonstrably does not fire for 13 of 18 marker spellings, by
the same measurement as finding 1. Fixing `_CITATION_RE` per finding 1 closes this too.

## UPHELD — clauses of the claim that survived the attack

1. **"fail-closed" — upheld.** Traced every path. Before b8d4584, an unresolved marker on a
   RELATIONAL claim yielded GROUNDED and on an ABSENCE claim yielded ABSENCE_SUPPORTED; both
   now yield UNVERIFIED_CITATION. Every other branch is reached with an identical citation
   tuple. The `not claim.citations` → `UNCITED` branch is untouched because `any()` over an
   empty tuple is `False` (verified: the uncited absence draft still returns
   ABSENCE_SUPPORTED). **No input found where the change moves a claim toward PASS.**
2. **"exactly one call site each" — upheld.** `grep -rn --include='*.py'` over the whole
   repo excluding tests: `ground_relational` and `check_absence` are called only at
   `scripts/ground_check.py:2598` and `:2600`. `ground()` has exactly two callers —
   `score_report` (`:2883`) and `scripts/calibrate.py:186` — and `score_report` has two
   (`main()` at `:3002`, and `docs/research/diagnostic/union.py:28`). **No verdict, gate, or
   score path bypasses `ground()`**, so the calibration corpus and the CLI see the same
   verdicts. The gate/appendix construction in `score_report` introduces no independent
   verdict source.
3. **The `AssertionError` is fail-closed** (and dead). `resolve()` is pure and deterministic
   over `(citation, store)`, neither of which changes between the guard at `:2595` and the
   loop at `:2611`, so the raise is unreachable. If it were reached, an uncaught exception
   from `main()` exits **1**, not 0 — measured with a malformed store
   (`subprocess` returncode `1`). No fail-open.

## Cosmetic / lower-severity

- **cosmetic** — the unreachable `AssertionError` at `scripts/ground_check.py:2616` is dead
  code defending an invariant the caller cannot break. Harmless, but it is a deliberate
  simplification without a stated boundary: it would also convert a *library* consumer
  (`calibrate.py`) from "emits a verdict" to "aborts the run". One `CEILING:` line would
  record that.
- **cosmetic** — `evidence_basis` compounds finding 1 rather than catching it. On the PASS
  reproductions it reports "Checked verbatim against 2 cited sources: S1, S2" while a third
  marker sits in the sentence. The commit message's own argument for J-25 was that
  `evidence_basis` contradicted the verdict and was therefore the honest witness; with an
  unmatched marker both the verdict *and* the witness agree, and both are wrong. The
  self-contradiction that exposed R9P1-01 is not available here.

## Load-bearing assumption of THIS review

That a reader of the rendered draft treats a bracketed span such as `[s99]`,
`[Source:acme-internal-report]` or `[Ѕ99]` as a citation. If Agent-Assure's contract is
instead "only `[S<n>]` and `[source:<x>]` are citations; anything else is prose", then
findings 1 and 2 are Error-A-free product-scope questions rather than Error-B. I judge that
reading untenable for a gate whose deliverable is audit defensibility: the store's own
`source_id` space is unconstrained, the capture hook can mint any id, and a PASS certificate
is read by someone who never sees `_CITATION_RE`. But it is Sai's spec-source call, and it
is the one fact that would flip this verdict.
