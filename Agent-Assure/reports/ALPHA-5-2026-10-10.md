## A-5-01 — the installer's OWN snippet crashes in a fresh install. OWNER: SAI.

`install.sh` closes by telling a new user how to obtain a session id:

```
SID=$(.venv/bin/python -c "import json;print(json.loads(open('.assure/evidence-store.jsonl').readline()).get('session_id',''))")
```

Pasted verbatim into a freshly installed clone, that is:

```
FileNotFoundError: [Errno 2] No such file or directory: '.assure/evidence-store.jsonl'
```

**This is J-50's sibling, one layer out, and this morning's fix cannot reach
it** — the subshell dies before the CLI is ever invoked. The file it opens
**cannot exist** in a fresh install: the store is written by the PostToolUse
hook, so it appears only after the hook has fired at least once. So the last
thing `install.sh` prints to a brand-new user is a command that fails if they
paste it immediately, and fails with a traceback rather than a sentence.

**Severity is LOW and detectability is what makes it worth a row.** It costs a
tester nothing but confidence — and confidence in a verification tool is the
product. **It is NOT FIXED HERE: `install.sh` is Escalation #4 and on the park
list** (installers write into user repos). Two lines, Sai's file:

1. A line before the snippet: *the store does not exist until the capture hook
   has fired at least once, so run some research first.*
2. The `python -c` prints a sentence when the file is missing instead of
   raising — and **not** an empty string, which would hand `--session-id ""` a
   blank and produce today's refusal for a second, unrelated reason.

Point 2 is the one that matters: the obvious repair (`.get(..., "")` with a
`try`) is a **silent fallback** that turns a missing file into an unattributable
id, and the user would then be debugging the wrong message.
