## R15-01 — HIGH — `--session-id ""` buys the session-scope wording over a store with zero session information

**Class:** the scope statement lies (J-56 regression surface).
**The code.** `assert_single_session` builds
`{s.session_id or "<no session_id>" for s in store.values() if s.session_id != session_id}`.
A record with no `session_id` field loads as `""` (`load_store`, line 303). With
`session_id == ""` the comprehension's guard `"" != ""` is False, so the record is
never collected, `foreign` is empty, and nothing raises. `main()` then sets
`session_scoped=args.session_id is not None` → `True` → `_SCOPE_SESSION`.

**Reproduction — the SHIPPED demo store, no fixture needed.** Note the demo
store's records have no `session_id` field at all.

```
cd Agent-Assure
uv run python scripts/ground_check.py --draft demo/draft-grounded.md \
    --store demo/evidence-store.jsonl --session-id "" --json > out.json 2>&1; echo $?
```

Actual output (`exit=0`):

```
gate            = PASS
grounding_score = 100.0
scope           = "PASS means every claim in this draft is traceable to text in a
                   source retrieved this session; it does not mean the source agrees
                   with the claim, and a source that denies or hedges a claim can
                   still satisfy this check."
```

The unscoped run on the same inputs prints the truthful variant
("present in the evidence store supplied to this run … Session scope is NOT
asserted"). One empty-string argument swaps the claim the product makes about
its own evidence, over records that cannot be attributed to any session.

**Why the suite does not catch it.** `tests/test_session_scope.py::
test_an_unattributable_record_raises_under_enforcement` pins exactly this
property — but asserts it with `session_id="sess-A"`. The empty-string argument
is untested, and it is the one value for which the rule inverts.

**Severity is HIGH, not CRITICAL:** no verdict moves. `PASS 100.0` is reached
identically without the flag. What moves is the sentence the product uses to
describe what `PASS` covers — the single thing ADR-008 shipped.

**Related, same root, also reachable:** the scoped wording rests entirely on a
string inside the store file. `fetched_at` is the constant sentinel
`1970-01-01T00:00:00Z`, so nothing corroborates it temporally.

```
# record written with "session_id": "sess-OLD" (any prior session, any machine)
uv run python scripts/ground_check.py --draft A-draft.md --store O-store.jsonl \
    --session-id "sess-OLD" --json ; echo $?    # exit=0
→ gate=PASS  grounding_score=100.0  scope="…retrieved this session…"
```

**Control (fail-closed where it should be):** a store mixing a session-less
record with `"session_id": "sess-B"` under `--session-id ""` **does** raise
(`ValueError: … holds records from outside this session '': sess-B`, exit 1), and
a full-width `--session-id` against an ASCII record raises. The hole is
specifically the homogeneous session-less store — i.e. the common case.

## R15-02 — HIGH — one of the three published diagnostic rates uses the wrong denominator

**Re-derived independently** from `calibration/build_corpus_v2.build_candidate_cases()`
joined to `calibration/labels-v2.csv` by `claim_id`, calling
`ground()` and `support_diagnostic()` directly (52 rows, all `label_status=gold`):

| Published (CR-009 / README / SKILL / `commands/`) | Re-derived | Agrees? |
|---|---|---|
| All scored claims 10/52 = 0.192 | **10/52 = 0.192** | yes |
| **Claims the gate passes 4/15 = 0.267** ("1 in 4") | **4/15 = 0.267** | **yes** |
| Claims a human labelled grounded **7/27 = 0.259** | **7/25 = 0.280** | **NO** |
| Error-A 0.400 (10/25) | 10/25 = 0.400 | yes |
| Error-B 0.000 (0/27) | 0/27 = 0.000 | yes |

Gold label counts: **25 `grounded`, 27 `violation`** (sum 52). The row "claims a
human LABELLED grounded" is therefore `7/25 = 0.280`; `27` is the
labelled-**violation** count, borrowed from the Error-B denominator one row up.
The numerator 7 is correct. The published figure **understates** the
false-alarm rate on human-grounded claims (0.259 vs 0.280).

Appears in two places: `calibration/CR-009-accept-and-disclose.md:40`
(`| Claims a human LABELLED grounded | 7/27 = 0.259 |`) and
`tests/test_support_diagnostic.py:18` (module docstring, "25.9% of claims a
human …"). The headline **26.7% / "1 in 4" is correct everywhere** and needs no
change.

For completeness, re-derived and not previously published: fire rate on
human-labelled-**violation** claims = **3/27 = 0.111**. Firing rows:
`q03 q07 q31 q11 q34 q12 q17 q25 q28 q47`; firing **and** gate-passed:
`q03 q07 q11 q34`.

Reproduce: `calibration/build_candidate_cases()` → `classify(decompose(draft))`

## R15-03 — DIAGNOSTIC-GAP — the denial one sentence over is invisible

The diagnostic inspects **only** the single max-overlap sentence. A source that
restates the claim and then denies it in the next sentence — the ordinary shape
of a real negative finding — is not flagged. **This refuses nothing; it is a
missed warning, not an Error-B.** The `PASS` was already available before J-74.

Store (`A-store.jsonl`, one line, pasted verbatim from the fixture that produced
the output below; `content_sha256` is `sha256(NFKC(text))`, though `load_store`
does not recompute it — documented CEILING / J-32):

```json
{"source_id": "S1", "url": "https://example.com/S1", "file_path": null, "fetched_at": "2026-06-28T00:00:00Z", "tool": "mcp__exa__web_fetch_exa", "content_sha256": "b8885fadd3d0321ca71d9ed3a228f8b8bc9a0548f8d153b4a151a4673c461cce", "text": "The Mumbai regional cluster processed 128000 payment transactions during the audited quarter. Our independent reconciliation did not reproduce that total and we found no evidence supporting it.", "full_text_source": "verbatim", "captured_via": "inline", "query_provenance": "throughput audit"}
```

Draft (`A-draft.md`, exact):

```
The Mumbai regional cluster processed 128000 payment transactions during the audited quarter [S1].
```

Command and actual output:

```
uv run python scripts/ground_check.py --draft A-draft.md --store A-store.jsonl --json > out.json 2>&1; echo $?
→ exit=0
gate=PASS  grounding_score=100.0  scored_claims=1
per_claim[0] = {
  "index": 0, "kind": "NUMERIC", "verdict": "GROUNDED",
  "evidence_basis": "Checked verbatim against 1 cited source: S1 (193 chars).",
  "support_diagnostic": "no_hedge_in_cited_sentence"
}
```

The cited source says *"did not reproduce that total and we found no evidence
supporting it"* — `not`, `no` are both in `_SPAN_HEDGE_TOKENS`. They are one
sentence boundary away and are never read. Three runs byte-identical
(md5 `6ee8d6c395da8369a78d4f4045156be5`).

## R15-04 — DIAGNOSTIC-GAP — the denial *inside* the inspected sentence, in words the lexicon does not hold

Same vector class, stronger: the denial is in the max-overlap sentence itself and
is still missed, because `_SPAN_HEDGE_TOKENS` holds `refutes`/`disputes`/`false`
but not `debunked`, `erroneous`, `retracted`, `rebutted`. The comment above the
function argues the reuse is Chesterton's Fence — correct as a change-control
argument, and this is the bill for it.

Store (`B-store.jsonl`, one line; same envelope as R15-03, `text` only):

```
"The Mumbai regional cluster processed 128000 payment transactions during the audited quarter, a total our forensic review debunked as erroneous, later formally retracted by the vendor and rebutted in court."
```

Draft: identical to R15-03.

```
uv run python scripts/ground_check.py --draft B-draft.md --store B-store.jsonl --json > out.json 2>&1; echo $?
→ exit=0
gate=PASS  grounding_score=100.0
per_claim[0] = {"index":0,"kind":"NUMERIC","verdict":"GROUNDED",
  "evidence_basis":"Checked verbatim against 1 cited source: S1 (206 chars).",
  "support_diagnostic":"no_hedge_in_cited_sentence"}
```

Vectors additionally confirmed as not-in-lexicon by the same construction:
`lacks`, `absent`, `fails to`, `rather than`, `zero`, `none`. A missing member
here points *away* from a flag, which is the safe direction for a report and
exactly the direction that makes a promotion to a verdict (J-70) unsafe.

## R15-05 — DIAGNOSTIC-GAP — the tie-break discards the denying sentence

`_most_overlapping_sentence` gives ties to the **first** sentence. Build two
sentences with an *identical* content-word intersection with the claim — a
restatement and an explicit refutation of it — and put the restatement first.

Store `C1-store.jsonl` text:

```
"The Mumbai regional cluster processed 128000 payment transactions during the audited quarter. The assertion that the Mumbai regional cluster processed 128000 payment transactions during the audited quarter is false."
```

Measured overlap, both sentences: **10 and 10** (a true tie).

```
uv run python scripts/ground_check.py --draft C-draft.md --store C1-store.jsonl --json; echo $?
→ exit=0   gate=PASS grounding_score=100.0 verdict=GROUNDED
           support_diagnostic=no_hedge_in_cited_sentence
```

The same two sentences in the opposite order (`C2-store.jsonl`):

```
→ exit=1   gate=FAIL grounding_score=0.0 verdict=UNGROUNDED
           support_diagnostic=cited_sentence_may_not_assert_claim
```

Identical bytes of evidence, identical claim; the author's sentence **order**
decides whether the reader is warned. Deterministic (the docstring is honest
about "arbitrary but deterministic"), and still author-controlled — the thing
`CLAUDE.md` warns about under "never key a moat rule on a surface property the
author controls". It is a *report* here, so it is a gap and not an Error-B.

## R15-06 — DIAGNOSTIC-GAP (noise direction) — `per` is a hedge token, so "operations per second" always fires

`_SPAN_HEDGE_TOKENS` includes `per` (for "according to"/"per the vendor"). Any
claim or source sentence containing the ordinary rate word `per` therefore
flags, with no attribution or denial present anywhere.

Store text (one sentence, no hedge of any kind):

```
"The regional throughput reached 128000 operations per second in every audited quarter. Our own measurement did not reproduce that figure and we found no evidence for it."
```

Draft: `The regional throughput reached 128000 operations per second in every audited quarter [S1].`

```
→ exit=0  gate=PASS grounding_score=100.0 verdict=GROUNDED
          support_diagnostic=cited_sentence_may_not_assert_claim
```

It fires here for the *wrong reason* — `per`, not the denial in the next
sentence (R15-03 shows the denial alone does not fire). This is a component of
the published 26.7%: the rate is partly measuring a unit word. It costs nothing
today (nothing is refused) and would be a direct Error-A generator the day the
signal is promoted. Worth naming because the CEILING comment attributes the
over-flagging to "the study found no link / no study found a link" ambiguity,
which is not what is happening in this row.

## R15-08 — DOC-DEFECT — "Every captured record now carries a `session_id`"

`README.md:180`. `capture_hook._event_session_id` returns `""` when the hook
event has no `session_id` or it is not a `str` (pinned by
`tests/test_session_scope.py:177-178`), and `capture_core` writes that through.
So records carry the **field**, frequently with no **value** — which is precisely
the state R15-01 exploits. The sentence reads as a provenance guarantee and is
the reason the empty-id hole looks closed from the documentation. Suggested
truthful form: "every captured record carries a `session_id` field, empty when
the harness did not supply one; an empty id cannot be attributed to a session."

## WHAT I ATTACKED AND COULD NOT BREAK

Load-bearing: these are clean results on named attacks, not silence.

1. **Verdict invariance under `session_scoped` (Attack 1 — the one that mattered).**
   135 pairs = 9 stores (`tests/**/*.jsonl`, `demo/`, `calibration/`) × 15 drafts
   (`demo/draft-grounded.md`, `demo/draft-fabricated.md`, `tests/honest_drafts/fixtures`,
   `tests/red_team_moat/fixtures`, `tests/fixtures`), plus 8 synthetic drafts
   (empty, whitespace-only, punctuation-only, non-claim, uncited, fabricated `[S9]`,
   absence, relational). For every pair: `score_report(..., session_scoped=False)`
   vs `session_scoped=True`, `scope` key popped, `json.dumps(sort_keys=True)`
   compared. **0 differences** — `gate`, `grounding_score`, `scored_claims`,
   `vacuous`, every `per_claim[].verdict`, `retained_appendix` all identical.
2. **`per_claim[].verdict == ground(claim, store).value`** for every claim in
   every pair above — the diagnostic is not displacing the verdict it sits beside.
   **0 mismatches.**
3. **`support_diagnostic` does not mutate the store.** It is called *between*
   `ground()` calls inside the `score_report` loop, so a mutation would leak into
   the *next* claim's verdict. `load_store` re-read and compared field-by-field
   after a full run: identical. `resolve()` is a `dict.get`; no module-level
   cache, no `lru_cache`, no global state anywhere in the call tree.
4. **Crash hunt (Attack 4).** 16 source shapes × 5 drafts = 80 pairs, all through
   `score_report`: empty source text, punctuation-only, whitespace-only, no
   sentence terminator, `"Clause No. 5 …"`, ellipsis, semicolon, em-dash,
   newline bullet list, NBSP-joined, full-width, combining marks, zero-width
   space, astral-plane emoji, stop-words-only source, 10 000-sentence source;
   drafts: normal, stop-words-only, empty, citation-only, 5 000-word claim.
   **0 exceptions.** `text=""` → `no_cited_verbatim_source` (the truthy guard
   holds); `full_text_source="haiku_summary"` → `UNGROUNDABLE` +
   `no_cited_verbatim_source` (the diagnostic respects the tier rule);
   unresolvable `[S9]` → `UNVERIFIED_CITATION` + `no_cited_verbatim_source`.
   Every "I don't know" in the diagnostic lands on a *non*-flag, which is
   display-safe because nothing reads it.
5. **Determinism.** Every edge pair run twice in-process: byte-identical. The
   R15-03 fixture run three times through the CLI: md5 identical ×3
   (`6ee8d6c395da8369a78d4f4045156be5`).
6. **Cost.** The diagnostic is cheap and linear: on a 10 000-sentence source,
   `ground()` = 28.07 s, `support_diagnostic()` = 0.05 s, `evidence_basis()` =
   0.00 s. The ~91 s whole-gate time on that input is pre-existing T1/T2 cost,
   **not** J-74. No denial-of-service surface added.
7. **`--session-id` fail-closed paths.** Mixed store (session-less + `sess-B`)
   under `--session-id ""` → raises, exit 1. Full-width `--session-id` against an
   NFKC-normalized ASCII record → raises. A genuinely foreign id → raises with
   the foreign id named. Only the homogeneous session-less store leaks (R15-01).
8. **"The word *verified* is deliberately absent from this tool's output" —
   TRUE.** Checked three ways, not three spellings: (a) AST walk over every
   string constant in `scripts/ground_check.py` — the only hits are the four
   `UNVERIFIED_*` verdict names, the input-side factive-verb lexicon at line 1317
   (`verify`/`verifies`/`verified` as *source* vocabulary, never emitted), and
   docstrings; (b) `grep -io "verif[a-z]*"` over the actual JSON report for the
   grounded draft → **0 hits**, and for the fabricated draft → 4 hits, all
   `UNVERIFIED` (which points away from PASS); (c) the human CLI path → two lines,
   `gate=… grounding_score=…` and the scope statement, neither containing the
   token. No output string asserts verification.
9. **No verdict path references the new display layer.** The two AST guards
   (`tests/test_scope_statement.py::test_no_verdict_path_consults_the_scope_statement`,
   `tests/test_support_diagnostic.py`) run green, and I re-checked `ground`,
   `check_absence`, `ground_relational`, `classify` by reading them: no
   reference to `scope_statement`, `_SCOPE_*`, or `support_diagnostic`.
10. **Suppression of a flag by adding a clean second source.** `support_diagnostic`
    is `any`-semantics over cited sources and returns on the first hit, so adding
    an innocuous `[S2]` to a flagged claim does **not** clear the flag. Could not
    break.
11. **Targeted suite.** `tests/test_support_diagnostic.py tests/test_scope_statement.py
    tests/test_session_scope.py tests/honest_drafts tests/test_product_claim.py`
    → **65 passed, 3 xfailed**, consistent with CR-009's "7 passed / 3 xfailed"
    on `honest_drafts`.
