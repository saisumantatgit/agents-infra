## R16-03 — HIGH — the recorded masking mechanism for J-33 does not reproduce; it is misdiagnosed

`tests/red_team_moat/test_moat_j33_unrecognised_citation_open.py` (lines ~205–260)
and the D-46 narrative both state:

> "`X200` extracts as the numeric token `200` (J-72), `200` is in no source, and
> the claim was refused as UNVERIFIED_NUMBER"

**`200` IS in both sources.** Both `ABS` records contain the literal string
`X200`, and `_extract_numeric_mentions` reads `(200.0, 'absolute', None, None)`
from each:

```
_extract_numeric_mentions("No recall evidence was found in the manufacturer's safety bulletin archive for the X200 drone line.")
  → [(200.0, 'absolute', None, None)]
_extract_numeric_mentions("The public recall database returned zero results for X200 drone safety evidence.")
  → [(200.0, 'absolute', None, None)]
```

What actually refuses the fixture is the **digits of the unrecognised citation
marker itself**. `_CITATION_RE` does not match `[s99]`, so the marker is never
stripped from the numeric-extraction scratch copy and `99` becomes a claim
numeric token:

```
classify("[s99] We found no evidence of a safety recall affecting the X200 drone.")
  → kind=ABSENCE  citations=()  numeric_tokens=('99', '200')
classify("[Ѕ99] ...")  (Cyrillic Ѕ)
  → kind=ABSENCE  citations=()  numeric_tokens=('99', '200')
classify("We found no evidence of a safety recall affecting the X200 drone.")
  → numeric_tokens=('200',)

numeric_ok(claim, ABS) with ('200',)        → True
numeric_ok(claim, ABS) with ('99','200')    → False     ← this is the refusal
```

Three consequences, all load-bearing:

1. **The register's stated upgrade path is wrong.** Fixing J-72 (stop reading
   model numbers as quantities) would **not** unmask J-33 — `99` would still be
   extracted and still refuse. Anyone acting on the recorded reason will fix the
   wrong thing and find the tripwire unchanged.
2. The CONTROL test's assertion message — *"the MODEL NUMBER is what refuses this
   fixture, not the marker"* — asserts the exact inverse of the truth. It is the
   **marker**, by way of its digits.
3. It is a wider mask than recorded: **any** unrecognised citation marker
   containing digits injects a phantom numeric token, so the figure check now
   pre-empts the J-33 absence shape for every such marker, independent of whether
   the subject names a model.

Severity HIGH rather than DOC-DEFECT because a recorded mechanism that does not
reproduce is the thing the register exists to prevent, and this one is written
into both a test docstring and an assertion message.

## WHAT I ATTACKED AND COULD NOT BREAK

1. **Toward-PASS motion — the only CRITICAL category. Clean, and structurally so.**
   3,705 differential absence comparisons (13 subjects × 5 templates × 57 stores:
   all 52 corpus stores, the demo store, and 4 adversarial stores of mine),
   `ground()` vs. `check_absence()` called directly with the same arguments:
   **1,910 verdict changes, 0 toward PASS.** The structural argument backing the
   measurement: both new returns are `Verdict.UNVERIFIED_NUMBER`, which is not in
   `_NUMERATOR_VERDICTS = {GROUNDED, ABSENCE_SUPPORTED}`, so the row lands in
   `retained_appendix` and ADR-005's empty-appendix cap blocks PASS regardless of
   score. There is no code path by which an early `UNVERIFIED_NUMBER` return can
   produce a numerator verdict.
2. **Skipping, not just refusing.** The thing I expected to find and did not: a
   claim that `check_absence` would have refused **and whose refusal was the only
   thing blocking PASS** now returning something weaker. Every observed skip
   substitutes one violation-class verdict for another (R16-01), never a
   numerator one.
3. **Ordering above the figure checks is intact.** `UNVERIFIED_CITATION` still
   wins over the figure refusal: `"[S99] We found no reports of battery defects
   in the 4200 unit service manual."` against `store-a3.jsonl` → `UNVERIFIED_CITATION`,
   while `[S1]` on the same draft → `UNVERIFIED_NUMBER`. J-25's provenance-first
   guarantee survives the insertion.
4. **The verbatim-basis check (R10C-03) still precedes the figure checks.** A
   store of only `haiku_summary` records returns `UNVERIFIED_ABSENCE`, not a
   figure verdict, and `_absence_verbatim` is non-empty by the time the figure
   checks run — so neither can be reached with an empty source list and neither
   can be fooled by a summary.
5. **A figure living only in a `haiku_summary` cannot certify.** `store-summfig.jsonl`
   (verbatim basis present, `4200` only in the summary) → `UNVERIFIED_NUMBER`
   (before: `ABSENCE_SUPPORTED`). The summary-may-refuse-never-approve asymmetry
   is preserved on the new path.
6. **Empty-text records.** `_absence_verbatim` filters on `source.text`, so a
   verbatim record with `text: ""` contributes nothing to the figure check — the
