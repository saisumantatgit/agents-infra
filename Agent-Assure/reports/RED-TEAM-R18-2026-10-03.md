## R18-03 — CRITICAL — the draft's own `query_provenance` DILUTES the blanket-corpus-word denominator and switches a refusal off

D-54's recorded reasoning is that *shrinking* the query list is fail-OPEN because
it can disable the blanket-corpus-word refusal. **Growing it is fail-OPEN through
the same gate**, and that is not recorded anywhere. The rule is

```python
if len(distinct) >= 3 and 2 * len([q for q in distinct if head_noun in q]) > len(distinct):
    return Verdict.UNVERIFIED_ABSENCE
```

a **strict majority** test whose denominator is every distinct query in the
session. Adding queries that do *not* carry the head noun moves the ratio off
the majority and turns the refusal off. Reading the draft supplies such queries
at zero evidentiary cost, because a `Read`'s `query_provenance` is its file path.

`<R>/f8/draft-note.md`:
```
We found no changelog entry for the streaming ingest workload.
```
(no strong anchors; `head_noun = "changelog"`, so the blanket rule is live.)

`changelog`:
```json

{"source_id": "S2", ... "file_path": "/real/b.md", "tool": "Read", "text": "The repository history was reviewed in full.", "full_text_source": "verbatim", "query_provenance": "changelog ingest workload history", "session_id": "S-LIVE"}
{"source_id": "S3", ... "file_path": "/real/c.md", "tool": "Read", "text": "Maintainers publish summaries only.", "full_text_source": "verbatim", "query_provenance": "changelog streaming workload entries", "session_id": "S-LIVE"}
```
`<R>/f8/B-plus-self-reads.jsonl` = those three **plus three `Read` records of the

`note-copy-two.md`), each with the path as `query_provenance`.

**Which rule:** trace (`<R>` inline script) — A: 3 distinct queries, 3 carrying
the head noun, `2*3 = 6 > 3` ⇒ refused by the **blanket-corpus-word rule** inside

three added records are the draft.

`<R>/f8/C-genuine-dilution.jsonl`: the three self-reads replaced by three
*genuine* unrelated sources with paths as queries → **also
`ABSENCE_SUPPORTED`**. So the blanket rule is keyed on a ratio the author
controls by doing more irrelevant retrieval — the exact anti-pattern CLAUDE.md
names ("never key a moat rule on a surface property the author controls", killed
by token count in round 3 and by the Shift key in round 4). Self-reads are
simply the free way to set it.

Pre-existing at `754911b` and `88b1312`.

**Note on direction, honestly:** the `>= 3` gate and the majority test were both
re-validated on 2026-08-30 against four real Error-A cases, so a naive
tightening re-opens those. The defensible narrowing is to compute the ratio over
**counting-eligible queries only** (post-scope-filter, non-self), not over every
string in the store. That changes what can pass — Escalation #1.

## The load-bearing assumption of this report

That `_self_source_ids` is the only identity signal the gate has, so auditing
which *populations* consult it is exhaustive. If the right question is instead
"which population should a claim be checked against", then filtering sets one by
one is the same narrow-fix pattern as the four placement bugs — and the structural
answer would be to resolve the non-self population **once**, above the kind
dispatch, and pass only that to every basis, figure and tier check, keeping the
full store exclusively for refutation scans. Three of my four CRITICALs would
have been impossible to write against that shape. That is an architectural
change to what can pass, and therefore Sai's.
