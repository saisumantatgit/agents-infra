## R21-01 — The real exa server returns ONE block for a multi-URL fetch, so C2 and C3 never run | CRITICAL

**Mechanism.** C3 and C2 both hang off `_content_block_texts` (capture_core.py, `if len(blocks) < 2: return None`). With one block, `make_records` falls through to `make_record`, which takes `url = _url_from_input(tool_input)`, that is **`urls[0]`**, and stores the whole block as one verbatim text. The commit message says "make_records writes ONE RECORD PER CONTENT BLOCK", and its CEILING says "assumes a content block is the unit of 'one document'" and "no live multi-block exa capture exists". The live server shows the opposite unit: **one block holds every document**, separated only by exa's own `# Title\nURL: ...` headers. The branch therefore needs block count ≥ 2, and exa never produces that. C2 ("several URLs mean url=None") is keyed on BLOCK count, not on URL count, so a two-URL request gets `url = urls[0]`.

## R21-02 — C1 reads `isError` only on a dict; the live exa envelope is a top-level list. Failures record "ok" | CRITICAL (conditional trigger)

**Mechanism.** `_retrieval_status` (capture_core.py) has `if isinstance(tool_response, dict): if tool_response.get("isError") is True: return "failed"`. The module docstring and `tests/test_live_shapes.py:11` record the **live-validated** exa PostToolUse payload as a **top-level content-block list** `[{"type":"text","text":...,"_meta":...}]`. A list has no keys, so `isError` can never be seen there. The C1 test fixture (`{"content":[...], "isError": true}`) is a dict shape that appears in no live capture: Sai's real probe store has no exa record, and nothing in the repo shows an exa failure payload. Separately, I confirmed that the exa server does set `isError: true` at the protocol level (`exa_raw_2.out`: `isError= True nblocks= 1 text='Error fetching URL(s): https://www.ecb.europa.eu/press/zentara-bank-doesnotexist-r21.html: CRAWL_NOT_FOUND'`).

**LOAD-BEARING ASSUMPTION, stated plainly.** I could not capture what Claude Code's PostToolUse delivers for an MCP result with `isError:true`. It may (a) pass the content list as it does for successes, which drops the flag, (b) pass some dict that carries the flag, or (c) not fire PostToolUse at all. Under (a), C1 is blind to every exa failure. Under (c), the R20-04 trigger never happens live for exa and C1's `isError` branch is dead code. Only (b) makes C1 effective, and (b) is the one shape nobody has observed. Settling this takes one tap-hook capture of a failing exa fetch.

## R21-03 — A failed or blank fetch still satisfies the verbatim-BASIS requirement | CRITICAL (depends on J-42, open)

**Mechanism.** In `ground()`'s ABSENCE branch, the R10C-03/R17-01 basis gate is
```

           and s.source_id not in self_source_ids for s in store.values()):
    return Verdict.UNVERIFIED_ABSENCE
```
It tests `s.text` for truthiness. It does not use `_carries_retrieved_content`. A record with `retrieval_status:"failed"`, or one whose text is `"   "`, is a "verbatim source" for this purpose. ## R21-05 — C2's "certain" URL is certain only after filtering | MEDIUM (trigger speculative)

**Mechanism.** `_requested_urls` drops non-str and empty entries: `[u for u in urls if isinstance(u, str) and u]`. `make_records` then sets `url = urls[0] if len(urls) == 1`. A request for `["https://www.who.int/...", ""]` that yields two blocks credits BOTH blocks to who.int. Whatever the tool returned for the second entry is attributed to the first. A non-str entry has the same effect, and `query_provenance` then falls back to the session id (`edge_urls_nonstr`: `query_provenance = sess-r21`).
```
$ ./run.sh c2empty c2s2.md c2_empty.json
--- store
{"source_id": "S1", "url": "https://www.who.int/news/zentara-safety-review", ... "text": "WHO safety summary. ..."}
{"source_id": "S2", "url": "https://www.who.int/news/zentara-safety-review", ... "text": "Zentara was cleared by the European Medicines Agency for children aged four and above in every member state."}
gate exit=0
gate PASS 100.0
1 FACTUAL GROUNDED | Zentara was cleared by the European Medicines Agency for children aged four and above in every member state [S2].

**Honest limit.** exa returns one block regardless (R21-01), and its schema types `urls` items as strings, so this needs a per-URL-block tool that tolerates `""`. Count the RAW `urls` list (or any entry that was dropped) as "not certain".

**Q4 answer: does anything downstream fill a URL back in?** `ground_check.py` never reads `source.url` at all (`grep -n "\.url\b"` finds no use outside the dataclass). The WHO attribution therefore does not reappear in the verdict display. The reader still sees the first-listed URL as the thing that was "searched" for every block.

## R21-07 — Low-grade shape gaps | LOW

Capture-side, by the real hook (`edge_*.json`, outputs in `edge_*.out` and `edge_*.store.jsonl`):
```

- `code` as a string and `isError` as a non-bool are not live shapes, so the gaps are cosmetic. The predicate is still "anything but the exact typed flag counts as success", which is the fail-open direction.

- `evidence_basis` grammar: "1 of these **search** returned no content". `_plural(n, 'search','searches')` is applied after "of these", so a count of 1 produces the wrong form.

## TRIED AND HELD

1. **The AND conjunction is the only path to ABSENCE_SUPPORTED.** `grep -n ABSENCE_SUPPORTED scripts/ground_check.py` shows `check_absence`'s single `return Verdict.ABSENCE_SUPPORTED` (line 2863) and its two call sites, both inside `ground()` (3705, 3735). `score_report` only counts verdicts (`_NUMERATOR_VERDICTS`). No summary, relational or cited path produces ABSENCE_SUPPORTED. The second call's query list is a subset of the first's; both calls use identical `source_texts`. The conjunction holds as logic. Every bypass in this report works by putting a non-read into the "ok" population or the basis, not by getting around the AND.
2. **The C1 fixture shape is correctly refused.** `./run.sh base ecb.md base_err0.json base_err1.json` gave `retrieval_status:"failed"` on both, `gate FAIL 0.0 UNVERIFIED_ABSENCE`, and the basis names both as "returned no content".
3. **Legacy stores never certify.** I took the PASS control store (`ctrl`, two "ok" exa reads, `PASS 100.0 ABSENCE_SUPPORTED`) and (a) removed `retrieval_status`, (b) set it to `""`, (c) removed it from one record only. Results: `legacy_absent exit=1 FAIL 0.0 UNVERIFIED_ABSENCE`, `legacy_empty exit=1 FAIL 0.0 UNVERIFIED_ABSENCE`, `legacy_mixed exit=1 FAIL 0.0 UNVERIFIED_ABSENCE`.
4. **Unknown status values are refused at load.** `retrieval_status:"OK"` gave `REFUSED: ... field 'retrieval_status' must be one of ['', 'failed', 'ok'] or absent, got 'OK'.` (exit 1).
5. **Demo store regenerated (17a4405).** Only `retrieval_status` was added; the digests are byte-identical (`309d667a9212`, `257e37f8cb82`). `draft-grounded` gives PASS 100.0, and `draft-fabricated` gives FAIL 50.0 (UNVERIFIED_CITATION, UNVERIFIED_NUMBER). Nothing to report.
6. **Multi-block edge cases at capture.** `two_one_blank` gave S1 'Real page words here' ok and S2 '   ' failed (correct). `iserr_list_blocks2` (dict, isError true, 2 blocks) gave both blocks failed (correct). `one_block_list` with 2 URLs gave `url=urls[0]`, which is the R21-01 defect, not a pass.
7. **Splitting does not hide a contradiction that joining found.** The control store plus one 2-block fetch whose contradiction straddles the seam ("...the ECB published a press release on the resolution of" / "Zentara Bank, confirming...") gives `split FAIL 0.0 UNVERIFIED_ABSENCE`, the same as the joined equivalent (`joined FAIL 0.0 UNVERIFIED_ABSENCE`). The contradiction rule needs only the head noun plus one corroborator within one window, so either half alone refutes. I could not construct a split that moves toward PASS.
8. **An exa error that echoes the URL is refused** (`liveerr`: `"Error fetching URL(s): <url with zentara bank>: CRAWL_NOT_FOUND"` recorded "ok", but `FAIL 0.0 UNVERIFIED_ABSENCE` through RT3-04 contradiction). This held by accident of spelling; see the R21-02 sibling.

## SPECULATIVE (not driven to PASS)

- **Figure checks over failed bodies.** `_absence_verbatim` takes failed and blank verbatim records, so an error body's digits ("503", "404") could satisfy `numeric_ok` for an absence claim that carries the same figure. Not reproduced.
- **Overflow path (R20-05).** `reconstruct_text`'s overflow branch is untouched by C1, C2 and C3. An overflow file holding several documents is one record under `urls[0]`. It is the same as R20-05, still open, and the trigger shape is still unobserved live.
- **PostToolUse on MCP errors.** If Claude Code routes MCP `isError` results to a different hook event, C1's dict branch never runs for exa, and the true live failure surface is the partial failure inside a multi-URL "ok" block (`exa_raw_3.out`). One tap-hook capture settles this.

## Load-bearing assumption of this report

R21-01 rests on the exa server's protocol response (captured live) being what reaches `tool_response`. That matches the repo's own live-validated note: "TOP-LEVEL MCP content-block list ... _meta". If Claude Code re-split one MCP text block into several, R21-01 would fall. Nothing in the repo or in the observed payloads suggests it does.
