## R22-01: exa's live partial-failure text is recorded "ok", so an absence certifies on two failed ECB searches | CRITICAL

**Mechanism.** R21's own live capture `r21/exa_raw_3.out` (a two-URL fetch, one URL failing) shows exa's PARTIAL-failure form:
```
"# Example Domain\nURL: https://example.com\n\n...\n\nهذا النطاق مُخصص للاستخدام\n\nError fetching https://www.ecb.europa.eu/press/zentara-bank-doesnotexist-r21.html: CRAWL_NOT_FOUND"
```
This text has no section header before the error, so the failed page stays glued to the successful page's section. Its text is also "Error fetching <url>:", not "Error fetching URL(s):", so `_EXA_ERROR_PREFIX` would not match it even as its own section (probe: `err noURLs -> ok`). The record is "ok". `query_provenance` is `urls[0]` (capture_hook `_derive_query_provenance`), which is the URL that FAILED. `_carries_retrieved_content` passes, because the OTHER page supplied the words. So the absence count credits a search that returned nothing.

The echoed URL contains the query words, so the RT3-04 contradiction check usually refuses (`pf` below). That refusal is defeated whenever the echo shares a sentence-window with a negation word. `_split_sentences` splits only after `.!?`, so it is enough that the successful page ends with an unpunctuated line containing "no" or "not". The live example.com capture itself ends with an unpunctuated line.

**Reproduction.** Draft `ecb.md`: "There is no ECB press release on the resolution of Zentara Bank." The two events `pfl0.json` and `pfl1.json` each have `urls=[<ECB search URL>, "https://example.com"]` and `tool_response=[{"type":"text","text": <example.com section> + "\n\nCookies are not used on this site\n\nError fetching <ECB URL>: CRAWL_NOT_FOUND"}]`.
```
$ ./run.sh pfl ecb.md pfl0.json pfl1.json > pfl.out 2>&1; echo $?
0
{"source_id": "S1", "url": null, ... "text": "# Example Domain\nURL: https://example.com\n\n...Cookies are not used on this site\n\nError fetching https://www.ecb.europa.eu/search?q=zentara%20bank%20resolution%20press%20release: CRAWL_NOT_FOUND", ... "query_provenance": "https://www.ecb.europa.eu/search?q=zentara%20bank%20resolution%20press%20release", ..., "retrieval_status": "ok"}
{"source_id": "S2", ... same shape, second ECB URL ..., "retrieval_status": "ok"}
gate exit=0
gate PASS 100.0
0 ABSENCE ABSENCE_SUPPORTED | There is no ECB press release on the resolution of Zentara Bank.
   basis: ... Complete record consulted: 2 distinct search queries and the text of 2 retrieved sources. ...
```
The basis does not say that either search returned no content.

The same events on 74cfffb (`./run_old.sh pfl_old ...`) also give `gate PASS 100.0 ABSENCE_SUPPORTED`, so this is **pre-existing, not a regression**. 35a180f's R21-02 fix does not reach it.

Variants:
- `pf`: the same events without the negation line give `gate FAIL 0.0 UNVERIFIED_ABSENCE`. That refusal comes from the contradiction check reading the echoed URL, which is the same accident R21 recorded.
- `pfn`: the inline error with no URL echo ("Error fetching URL(s): CRAWL_TIMEOUT" appended after a successful section) gives `gate PASS 100.0` with no negation line needed. This shape is NOT observed live.

**Shape:** live-real. The partial-failure format is copied from exa_raw_3. The trailing unpunctuated line with "not" is ordinary page content and is NOT attacker-only. The order of exa's output relative to the `urls` order is unverified. If exa puts the error FIRST, the split gives the error its own section, which is still "ok" because the prefix differs (probe `noURLs`).

**Defeats:** R21-02 is incomplete. The prefix list covers only the whole-response failure form. R21-03's basis and figure-check narrowing cannot help, because the record really does carry content.

**Sibling:** the absence figure check (`_absence_verbatim`) accepts this record, so digits in the echoed failed URL (for example ".../report-4200") can satisfy `numeric_ok`. Not run separately. Systemic direction, not a fix: a multi-URL fetch should count only as a search for the URLs whose sections returned. The failure is per-URL, and `query_provenance=urls[0]` names one URL for the whole fetch.

## R22-02: header variants are not split, so the R20-01 cross-document span returns | HIGH (conditional)

**Mechanism.** `_EXA_SECTION_RE = (?m)^(?=# [^\n]*\nURL: \S)` requires exactly "# " at column 0, a title on one line, then "URL: " and a non-space character on the next line. Probe (`probe.out`, the number of pieces from `_documents` for a page A followed by a variant header for page B):
```
std 2 | crlf 2 | empty_title("# ") 2
nospace_hash("#B") 0 | h2("## ") 0 | lead_ws(" # ") 0 | url_nospace("URL:x") 0
blank_between 0 | empty_title_nospace("#") 0 | title_newline 0 | url_empty 0
tab_title 0 | nbsp 0 | u2028 0 | cr_only 0
```
Every miss JOINS two documents. That is the fail-open direction, because forgery adds splits but a missed real header removes one.

**Reproduction (real hook and CLI).** `seam.md`: "The Zentara inhaler was approved for use after a full regulatory review by the European Medicines Agency [S1]." Page 1 (WHO) ends "...approved for use after a full". Page 2's header is a variant, followed by "regulatory review by the European Medicines Agency...".
```
tnl     (header "# Zentara: EMA\nopinion\nURL: ...") : 1 record, gate PASS 100.0, GROUNDED
notitle (header "#\nURL: ...")                         : 1 record, gate PASS 100.0, GROUNDED
stdhdr  (control, header "# EMA\nURL: ...")            : 2 records, gate FAIL 0.0, UNGROUNDED
```
`url` is null in both PASS cases, so there is no misattribution. The Error-B is a sentence that neither document contains, certified at 100.0.

**Shape:** speculative. Only "# <title>\nURL: <url>" has been observed live. A title with no text, or one containing a newline (an HTML `<title>` can contain one), is plausible for exa but unverified. A missed split needs exa itself to emit the variant. A page cannot remove exa's real header.

**Defeats:** R21-01 on non-canonical headers.

**Sibling:** `_documents` splits only when `_block_list` sees a LIST. An exa response delivered as a plain str, or as `{"text": str}`, is one record (probe: `str 1 [None]`, `dict 1 [None]`). The url is correctly None there, but spans still cross. Not a live shape.

## TRIED AND HELD
1. **The canonical live split holds.** `stdhdr` (above) gives 2 records and FAIL 0.0. `crlf` and `empty_title "# "` split (probe).
2. **Attribution.** A multi-URL fetch gives url null in every record (pf, pfl, tnl). A single URL with a forged header credits both pieces to the one requested URL (`single+forged [('https://a',..),('https://a',..)]`), which is truthful because both are that fetch's bytes. `{"url":a,"urls":[]}` gives None. `{"url":a,"urls":None}` gives a. The header's URL: line is never used. DDG text with exa-like headers is not split and is credited to its single requested url (`ddg exa-like`), which is correct. A WebFetch result block list gives 2 records, both `haiku_summary` with the requested url. `ground_check.py` never reads `.url`. The only URL shown to a reader is `query_provenance` (urls[0]) in the absence basis, which is R21's Q4 and still open (see R22-01).
3. **query_provenance is the same on every split record.** `make_records` passes one value to every piece. `make_record` takes the same argument. The hook derives it once per event. In pf, pfl and pfn each event produced one distinct query.
4. **Null and empty cases.** One empty block gives one "failed" record. Two empty blocks give one "\n" record, "failed". `[]`, `{"content":[]}` and `{"text":[]}` raise TypeError, so the hook logs "capture skipped" and stores nothing (fail-closed). A header-only section ("# A\nURL: x\n") is "ok", the same as before the fix, and is a real empty-page fetch.
5. **Split abuse.** Splitting can only separate a head noun from its corroborator, and only across a header. On the live format that header is exa's own page boundary, and a contradiction formed across two pages was spurious. A forged header inside a page that refutes the claim needs the attacker to control the refuting page, and an attacker who did would simply omit the refutation. No PASS was constructed. R21's straddling-contradiction test also held.

## SPECULATIVE
- Whether exa orders its output by `urls` order, and whether it ever puts a partial error first. This decides whether R22-01 needs the negation line at all.
- Whether exa emits titles that are empty or contain a newline (R22-02). One live fetch of a page with no `<title>` would settle it.

## Load-bearing assumption
R22-01 assumes exa's partial-failure form in `r21/exa_raw_3.out` (the error appended inline, beginning "Error fetching <url>:") is what reaches the hook. That file is a raw JSON-RPC protocol response, not a captured PostToolUse payload.
