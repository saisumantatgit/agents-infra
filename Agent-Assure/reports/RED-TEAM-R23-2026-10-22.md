## R23-01 — A failed fetch grounds a fabricated claim through the URL echoed in exa's error text | CRITICAL

**Mechanism.** exa's failure text echoes the requested URL: the whole-failure form `Error fetching URL(s): <url>: CRAWL_NOT_FOUND` (live, `exa_raw_2`) and the partial form `Error fetching <url>: CRAWL_NOT_FOUND` (live, `exa_raw_3`). R22's fix now marks such records `retrieval_status: "failed"`, but that status is consulted ONLY on the ABSENCE branch of `ground()` (basis, content-store count, absence figure check). The positive path (`ground()` lines ~3779-3812: `verbatim` list -> `numeric_ok` -> `spelled_quantity_ok` -> `t1_verbatim`) never reads it. `t1_verbatim` tokenizes with `\w+`, so a hyphenated URL slug becomes ordinary words, and 8 contiguous tokens from the claim are found in the echo. The agent chooses the URL, and LLM agents routinely GUESS slugged URLs; a guessed URL that 404s therefore becomes the "source" of exactly the sentence the agent made up.

**Reproduction (HEAD, real entry points).** Draft `draft2.md`: `Zentara Bank was sanctioned by the ECB for serious AML failures [S1].` URL U = `https://www.ecb.europa.eu/press/pr/date/2026/html/ecb.pr-zentara-bank-was-sanctioned-by-the-ecb-for-serious-aml-failures.html`.
- `evC.json`: `urls=[U]`, `tool_response=[{"type":"text","text":"Error fetching URL(s): U: CRAWL_NOT_FOUND"}]` (live whole-failure form).
- `evD.json`: `urls=[U,"https://example.com"]`, one block = example.com section + `\n\nError fetching U: CRAWL_NOT_FOUND` (live partial form).
```
$ ASSURE_EVIDENCE_STORE=sC.jsonl uv run python scripts/capture_hook.py < evC.json   -> exit 0
"url": "https://www.ecb.europa.eu/press/pr/date/2026/html/ecb.pr-zentara-bank-was-sanctioned-by-the-ecb-for-serious-aml-failures.html"
"retrieval_status": "failed"
$ uv run python scripts/ground_check.py --draft draft2.md --store sC.jsonl --session-id sess-R23 --json   -> exit 0
PASS 100.0
GROUNDED | Zentara Bank was sanctioned by the ECB for serious AML failures [S1]. | Checked verbatim against 1 cited source: S1 (165 chars).

(evD) "url": null  "retrieval_status": "failed"   -> exit 0
PASS 100.0
GROUNDED | ... | Checked verbatim against 1 cited source: S1 (278 chars).
```
The basis says "Checked verbatim against 1 cited source" and nowhere says that source is a failed fetch.

**Pre-fix, same inputs:**
```
1ae81d9   C status failed  PASS 100.0 GROUNDED     D status ok  PASS 100.0 GROUNDED
35a180f~1 C status ok      PASS 100.0 GROUNDED     D status ok  PASS 100.0 GROUNDED  (D also stored url=U, the guessed failed URL)
```
Pre-existing; not a regression. What changed is that HEAD now KNOWS the record failed and certifies anyway.

**Control.** A figure in the slug was refused: `...fined-4200-million-euros...` with claim "fined 4200 million euros" gave `UNVERIFIED_NUMBER`, FAIL 0.0 (`gA.out`, `gB.out`). The hole needs a figure-free claim, which is the common case.

**Shape:** live-real. Both error formats are copied from R21's live exa captures. The only agent behaviour needed is fetching a guessed URL that 404s and citing it, which is a known hallucination pattern, not an attack.

**Defeats:** neither fix. ad9367d's message states the design choice that leaves it open: "Honest quotes from the working page still ground: retrieval_status gates only absence counting". A whole-failure record has no working page at all.

**Sibling.** (1) Any tool whose error body echoes the request (DDG 404 pages, per R21) grounds positive claims the same way; DDG has no "failed" signal at all. (2) R21-03's sibling fix narrowed only the ABSENCE figure check to content-bearing sources; the positive `numeric_ok` still reads failed records, so a slug figure in a form the extractor accepts would pass too (not constructed). (3) Point 4 of the brief: on HEAD the single-URL failed record still STORES the guessed URL as `url` (evC). `ground_check.py` does not display `.url`, so this is shown only in the store, not the report.
**Systemic direction (not a fix):** a record whose status is "failed" must not be a citable source for ANY claim kind; and for a partial failure, the error line (which is exa's text, not the page's) should be excluded from the groundable text, since the failed-record rule would otherwise also block honest quotes from the working page.

## SPECULATIVE
- Under-matching: `_EXA_ERROR_LINE_RE` misses other invisible leaders (U+200C, U+200D, U+2060, U+00AD), a non-ASCII space between "Error" and "fetching", and markdown-wrapped forms (`**Error fetching**`). None observed live; each only restores pre-fix behaviour.
- Whether exa ever reports a partial failure with wording other than "Error fetching" (e.g. a distinct code line). Not observed.

## TRIED AND HELD
1. **Over-match cannot remove a refusal (attack 1).** `ground()` reads `retrieval_status` only via `_carries_retrieved_content` at three places, all refusal-direction: the absence BASIS (existence test), the SECOND `check_absence` call (conjunction with the first, whose query list and blanket-word denominator still use the whole store), and the absence figure list. `source_texts` for the contradiction check is `store.values()` regardless of status. Run: a page that CONTRADICTS "There is no ECB press release on the resolution of Zentara Bank." and also contains a line "Error fetching the archive widget" -> that record "failed", the other two "ok" -> `FAIL 0.0 UNVERIFIED_ABSENCE` (exit 1). Contradiction still fired.
2. **Status is response-wide.** Every split piece calls `_retrieval_status` with the whole `tool_response` haystack (`_block_list` joined), so a split cannot leave one piece "ok" while another carries the error (evD: single record, "failed").
3. **Loose split (attack 3).** Every piece gets the same `query_provenance` and its own source_id; a header-only piece adds no distinct query, so no count or denominator moves. Extra splits only stop spans crossing.
4. **Pre-fix vs HEAD.** No input tried moved toward PASS between 1ae81d9 and HEAD.

## Load-bearing assumption
R23-01 assumes the agent can cite the store id of a failed fetch, i.e. that the agent sees (or can guess) source ids such as S1. If citations are assigned only to records the agent was shown as successful, the shape needs that link too. The live error formats themselves are from R21's raw protocol captures, not a PostToolUse capture.
