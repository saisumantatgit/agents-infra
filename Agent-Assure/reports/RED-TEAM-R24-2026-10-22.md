## R24-01 — the new any-envelope split computes retrieval_status per PIECE, un-failing R22-01's partial-failure rule | HIGH

**Mechanism.** R22-01's rule (capture_core.py comment at `_EXA_ERROR_LINE_RE`): "ANY such line marks EVERY record of that response failed", because the fetch's single `query_provenance` (urls[0]) cannot say which URL succeeded. `_retrieval_status` implements it by searching `_block_list(tool_response)` joined. ca466a4's new branch in `make_records` splits text for a plain-string / dict-`"text"` / overflow envelope, but `_block_list` returns None for those, so `haystack = text` = the PIECE. exa appends the partial-failure line after the LAST page, so only the last piece is "failed"; every earlier piece is "ok" and carries urls[0] — the URL that failed — as its search label. Before ca466a4 the same envelope was one unsplit record containing the error line, hence "failed".

**Reproduction** (real hook + real CLI, no network). Two fetches, each `urls=[<ECB search URL that failed>, example.com, iana]`, text = page example.com, page iana, then `Error fetching <ECB URL>: CRAWL_NOT_FOUND` (R22-01's live format). Draft: `There is no ECB press release on the resolution of Zentara Bank.` The ECB URL carries `&archive=none` (see note).

```
== h2-str   (HEAD, plain-string envelope)
S1 ok     '# Example Domain\nURL: https://example.com ...'
S2 failed '# Example Domains\nURL: https://www.iana.org/help/e...'
S3 ok     ...   S4 failed ...
exit=0
PASS
ABSENCE_SUPPORTED | ... 2 distinct search queries and the text of 2 retrieved sources. The queries were: "https://www.ecb.europa.eu/search?q=zentara%20bank%20resolution%20press%20release&archive=none"; ...
== p2-str   (parent ca466a4~1, same events)
S1 failed  S2 failed
exit=1
FAIL  UNVERIFIED_ABSENCE
== h2-blocks (HEAD, live block-list envelope)  all 4 failed, exit=1 FAIL UNVERIFIED_ABSENCE
```
The same bytes in the block-list envelope are refused on HEAD: the decision now depends on the envelope. Both ECB searches failed; the absence is certified on example.com/iana text labelled as the ECB search.

**Note on `&archive=none`.** Without it HEAD also refuses (st-head-str: FAIL), but only incidentally: the FAILED piece's text echoes the ECB URL, and the contradiction check (which reads the whole store) sees "zentara"+"release" in it. A `none`/`no`/`not` token anywhere in that sentence makes `_ABSENCE_NEGATION_RE` read it as a negated mention and skip it. Confirmed: dropping the failed records (okonly.jsonl) gives PASS 100.0 with no URL change. The refusal that remains is an accident of URL wording, not R22-01's rule.

**Shape:** attacker-only on current evidence. Live exa (R21 capture) returns a block list, which is handled correctly. ca466a4 added this branch precisely because review PR12 argued the other envelopes occur (plain str, dict text, overflow file); if they do, this is live.
**Fix defeated:** R22-01 (for every non-block envelope). Introduced by ca466a4; not pre-existing.
**Sibling:** the overflow-file envelope uses the same branch (`reconstruct_text` → piece haystack), so it has the same defect; not run separately. An error line placed BEFORE the first header (pre-header piece) would leave every page piece "ok" in the same way. Also, R23-01 (the slug echo) stays closed here only because the slug sits in the failed piece.
**Systemic direction (not a fix):** compute status once per RESPONSE from the full text `reconstruct_text` returned, and give every piece that one status, as the block-list path already does.
