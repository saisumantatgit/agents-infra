## Findings

- **MEDIUM-1: a comment claims an AST guard that does not exist.** The comment in `score_report` says "no verdict path may read it (pinned by an AST guard)". No test checks that `ground`, `_absence_chain` or the gate leave `absence_diagnostic` unread. The display-only property holds today only because the code happens to be written that way. ADR-007's `relation_diagnostic` has the same gap, so this repeats an earlier pattern. **Recommended fix:** either add the guard (an AST check that `absence_diagnostic` does not appear in `ground`, `_absence_chain`, or the score/gate computation), or remove the claim from the comment. Adding the guard is better: it is a few lines and it protects the demotion against later edits.
- **MEDIUM-2: a missing test would let a regression through.** The demotion is pinned only through particular fixtures. No single test asserts that `ground()` cannot return `ABSENCE_SUPPORTED` for any input. Re-promotion is caught today because about 10 tests assert `UNVERIFIED_ABSENCE`, so the risk is low. One property-style assertion would make the invariant explicit, for example a guard that the `ABSENCE_SUPPORTED` name never appears in `ground`'s AST except inside the mapping.
- **LOW-1:** rename `test_absence_delegates_and_supported` to something like `..._chain_supports_but_ground_demotes`.
- **LOW-2:** `_NUMERATOR_VERDICTS` still lists `ABSENCE_SUPPORTED`. It is dead today and would silently start counting again if the demotion were reversed. Add a `CEILING:`/comment, or remove the entry.
- **LOW-3:** the absence text in evidence_basis should say that an absence claim is never certified (ADR-009), so a reader does not chase "the minimum".
- **LOW-4:** fix the J-42 wording conflict (repair vs demotion) between the R10C-03 docstring and the ADR.
